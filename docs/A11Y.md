# 无障碍树通道（a11y）

## 为什么要有第三路

原来服务只有视觉两路：YOLO 找"哪里像控件"，OCR 读"框里写了什么"。
网页和 Electron 应用还有一份现成的结构化描述——无障碍树（accessibility tree，a11y）。
它直接给出 `role`（button/link/textbox）、`name`（可读名称）和 `border box`（整块可点区域），
恰好补上视觉两路的短板：

| 场景 | 只有视觉 | 加入 a11y |
| --- | --- | --- |
| 纯图标按钮（无文字） | 有框、无语义 | `role=link name="地图"` |
| 整块按钮里的文字框 | 只框住文字，点击点偏 | 用 a11y 的整块矩形做点击点 |
| 页脚小字链接 | OCR 认不出 | 直接给全 |
| canvas / WebGL 画布 | 能看见、能读字 | a11y 树里根本不存在 → 视觉兜底 |

两者不是替代关系：**有 DOM 的地方 a11y 优先，canvas 与自绘控件视觉兜底**。

## 两种接入模式

请求里加一个 `a11y` 段（JSON）。三种写法：

```jsonc
// 1) 服务端自己连 DevTools 拉树（推荐：与截图同一时刻，坐标同源）
{"mode": "cdp", "cdp_url": "http://127.0.0.1:9222", "target": 0}

// 2) 调用方已经采好了树，直接提交
{"mode": "inline", "elements": [
  {"role": "button", "name": "登录", "rect": [1310, 12, 1378, 53]}
]}

// 3) 关闭（与不传等价）
{"mode": "off"}
```

- `mode` 省略时：有 `cdp_url` 视为 `cdp`，有 `elements` 视为 `inline`，否则 `off`。
- `supported target`：`/json/list` 里的页面序号，默认 0。
- `url`：可选，先导航再采树。
- `timeout_seconds`：CDP 超时，默认 20。
- `elements[].rect` 为 `[x1, y1, x2, y2]`，与截图像素同坐标系。

### 坐标基准

a11y 给的是 CSS 像素 / 视口坐标。截图若是按 `devicePixelRatio` 缩放过的，请自行换算后再提交
（`mode=cdp` 时服务端会读回 `innerWidth/innerHeight/devicePixelRatio` 放进 `viewport` 字段，
但不会替调用方缩放外部传入的截图）。

## 融合规则

`a11y.merge()` 是确定性的贪心一对一匹配，评分：

```
score = 0.5 × IoU + 0.3 × 包含率 + 0.4 × 文本相似度 (+0.1 若中心距很近)
候选条件：IoU ≥ 0.25  或  包含率 ≥ 0.80  或  中心距 ≤ max(12px, 0.25×短边)
```

三条设计约束：

1. **包含率是必需的**。视觉框常只覆盖按钮里的文字，a11y 框是整个按钮；
   只算 IoU 会把这类配对全部丢掉（实测 with_text 匹配率会卡在 44%）。
2. **文本比较前剥掉图标字体私有区字符**（U+E000–U+F8FF）。a11y 名称常以 `\ue619` 开头。
3. **不静默覆盖**。名称不一致的配对会打上 `conflict=true` 并计数，
   元素仍保留两边的原文，由调用方决定信谁。例外：`textbox` / `searchbox` /
   `combobox` / `spinbutton` / `slider` / `listbox` / `option` 这些"值型"角色，
   a11y 的 name 是标签、OCR 的 text 是值，属不同语义层，不算冲突，标签写进
   `a11y_label`（实测某 Gradio 界面 24 个配对里 11 个是这种，误报清零）。
4. **只追加视口内的 a11y 独有节点**。无障碍树包含整页（含未滚动到的部分），
   实测某仓库页 184 个可交互节点只有 82 个在视口内；把屏外的也塞进结果，
   等于给调用方一批点不到的坐标。屏外的计入 `skipped_offscreen` 并丢弃。

匹配上的元素会得到：

```jsonc
{
  "text": "登录",                 // 冲突时保留视觉原文；一致或视觉为空时用 a11y 名
  "role": "link",
  "a11y_role": "link",
  "a11y_name": "登录",
  "a11y_rect": [1310, 12, 1378, 53],
  "a11y_alignment": {"iou": 0.89, "text_similarity": 1.0, "distance_px": 3.2, "conflict": false},
  "a11y_filled": true,            // 仅当该元素原本无字、由 a11y 补上名称
  "sources": ["yolo+ocr", "a11y"]
}
```

只存在于 a11y 的元素会被追加为 `type="a11y_only"`，`source="a11y"`，`clickable` 依 role 判定。

## 实测（第二组：真实站点与桌面应用，2026-10-31）

同一台机器、同一 Chrome、1399×855 视口，a11y 走 CDP，视觉走 YOLO+RapidOCR，融合用本仓库 `merge()`：

| 页面 | a11y 节点/可交互 | a11y 耗时 | 视觉控件 | 视觉耗时 | 匹配 | 视觉侧命中 | a11y 侧命中 | 冲突 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| GitHub 仓库页 | 2856 / 184 | 0.8 s | 110 | 5.4 s | 79 | 71.8% | 42.9% | 1 |
| B 站首页 | 1098 / 84 | 0.3 s | 116 | 5.2 s | 61 | 52.6% | 72.6% | 8 |
| GPT-SoVITS webui（Gradio 4） | 636 / 40 | 0.17 s | 52 | 5.5 s | 24 | 46.2% | 60.0% | 0 |
| Excalidraw（canvas） | 4 / **0** | 0.007 s | 3 | 3.0 s | 0 | – | – | 0 |

读法：

- **a11y 快一个数量级**（0.2–0.8 s 对 3–5.5 s），命名率 88%–100%。
- **视觉侧命中率偏低不是缺陷**：OCR 把封面文字、说明文字也识别成控件，a11y 只认真正可交互的。
  视觉独有元素没有 a11y 确认，调用方应视为"可能是不可点文本"（见下面点击实验）。
- **B 站冲突 8 条**是真实语义差异：卡片 a11y name 是"306.7万 4935 14:34"（播放/弹幕/时长），
  视觉读的是封面上的字。两边都对，保留双侧原文。
- **GitHub 屏外丢弃 102 个**、SoVITS 11 个、B 站 15 个——这就是上面第 4 条规则的由来。
- Excalidraw 反向验证：a11y 全瞎，视觉 3/3 认出"登录账号"等按钮。

### 点击命中实验（本地构造页，含宽按钮 / 纯图标按钮 / 输入框 / canvas）

用融合结果的 `click` 坐标通过 CDP `Input.dispatchMouseEvent` 真实点击，再读页面状态：

| 控件 | 类型 | 点击坐标 | 结果 |
| --- | --- | --- | --- |
| 保存设置 | 普通按钮 | (61, 36) | 命中 b1 |
| 生成语音（320px 宽） | 宽按钮 | (286, 36) | 命中 b2 |
| OK | 64px 窄按钮 | (496, 36) | 命中 b3 |
| （无文字图标） | 纯图标按钮 | (568, 36) | 命中 b4，靠 a11y 补名"上传文件" |
| 请输入文本 | 输入框 | (145, 108) | 焦点落到 i1 |
| 开始 / 停止 / 重置 | 按钮 | (326/408/490, 108) | 全部命中 |
| hits: b1,b2,… | 纯文字 div | (19, 313) | 无反应——视觉独有、本就不该点 |

结论：**9 个元素里 8 个真实控件全部命中（含宽按钮与纯图标），唯一"失败"是页面上的纯文字块**，
它只有视觉来源、没有 a11y 确认——这正好说明 `sources` 字段该怎么用：
只有 `yolo+ocr` 的元素先别急着点，带 `a11y` 的才是有语义保证的可点控件。

## 可用性评分（判断"这套能不能用"）

`POST /api/v1/a11y/probe`（不需要截图）返回：

```jsonc
{
  "mode": "cdp",
  "node_count": 268,
  "elements": [ ... ],
  "stats": {"interactive_count": 35, "named_rate": 1.0, "coord_rate": 1.0},
  "verdict": {
    "strategy": "a11y_primary",     // a11y_primary | hybrid | vision_only
    "summary": "...",
    "checks": {"L1_tree_size": true, "L2_interactive_coverage": true,
               "L3_named_rate": true, "L4_coord_rate": true}
  }
}
```

阈值（经验值，可在 `a11y.py` 顶部调整）：

| 检查 | 条件 |
| --- | --- |
| L1 树规模 | AX 节点 ≥ 20 |
| L2 交互覆盖 | a11y 可交互数 / DOM 可见可点元素 ≥ 0.60 |
| L3 命名覆盖 | 可交互元素带 name 比例 ≥ 0.80 |
| L4 坐标可得 | 能取到 border box 的比例 ≥ 0.90 |

- 全过 → `a11y_primary`：直接用 a11y 的语义与点击框。
- L1 挂或可交互 = 0 → `vision_only`：典型 canvas / 自绘 UI。
- 其他 → `hybrid`：a11y 补语义，视觉补几何和缺口。

## 已知坑

1. **CDP WebSocket 报 403**：Chrome 拒绝不受信 Origin。本实现用 `suppress_origin=True`，
   否则需要给浏览器加 `--remote-allow-origins=*`。
2. **a11y 名称带图标字体私有区字符**：比较前必须剥 U+E000–U+F8FF。
3. **AX 可交互数可能多于 DOM 可见可点数**（实测 35 vs 32）：AX 含布局可及但视觉不明显的节点，
   报覆盖率时口径要写清。
4. **iframe / shadow DOM**：`getFullAXTree` 只覆盖当前 frame；跨域 iframe 需逐 frame 采集。
5. **虚拟列表**：只含当前渲染项，滚出视口的行不在树里。
6. **Electron 应用不一定开调试端口**：实测容器内 Linux QQ（NTQQ）加 `--remote-debugging-port`
   会让主进程直接崩溃退出，只能回滚；要给它做 a11y 需要另找注入点，别在生产容器上反复试。
7. **Linux 原生 GTK/Qt**：`org.a11y.Bus` 在跑但 `toolkit-accessibility=false` 时导出的树是空的，
   需先 `gsettings set org.gnome.desktop.interface toolkit-accessibility true`。
8. **Windows / Android**：分别走 UIAutomation 与 `adb shell uiautomator dump`，本服务未内置客户端。

## 依赖

`mode=cdp` 需要可选依赖：

```bash
pip install "label-controllers[a11y]"    # websocket-client
```

`mode=inline` 不需要额外依赖。
